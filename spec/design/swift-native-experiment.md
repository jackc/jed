# Native Swift core experiment

Approved 2026-11-05. **Linux correctness acceptance passes; performance acceptance
and the final freeze remain in progress.** The target is the supported
Rust/Go/TypeScript surface at `362e0798ac3a8bd04bd2da556044b6ec73bf468a`.
The language-neutral specification and shared corpus define behavior. Existing cores
provide implementation patterns, never authority over the spec. Ruby's frozen surface
is not a scope limit.

## Lifecycle and delivery

`impl/swift-native` is an independent handwritten Swift engine and SwiftPM library.
It cannot call another engine, run SQL subprocesses, or transpile engine logic.
Tests, conformance, code generation and benchmarks require explicit `swift-native:*`
mise tasks. No normal task depends on Swift, and this experiment adds no website
documentation, generated website references or live panels. Local examples and reports
live with the package. The experiment freezes on completion; future features do not
update it, and production delivery/promotion requires a separate decision.

Development and verification target Linux x86-64. Swift 6.4.2 is installed through
Swiftly in the current checkout environment. Keep host OS code isolated for eventual
Apple packaging, but macOS/iOS are **unverified** until their own builds and tests run.
The absence of Apple hardware is not a Linux completion blocker.

## Scope and acceptance

The [scope matrix](swift-native-scope.md) inventories actual specs, catalogs, grammar,
capabilities and fixtures. The [host/tool matrix](swift-native-host-matrix.md) inventories
embedding APIs, cursor and accounting boundaries, test adapters, process tests,
simulation and interchange. Together they are the completion checklist. Future TODO
features remain unsupported. Missing implementation is a failure, never a silent skip
or a changed expected answer. The current file contract is v50, including encryption
and relaxed durability; historical milestone descriptions do not narrow this target.

Completion requires all applicable shared suites and byte fixtures, bidirectional
plain/encrypted interchange, host/resource/failure/recovery/cancellation tests,
Linux multi-process locking and page service, applicable deterministic simulation,
PostgreSQL oracle verification and healthy default tasks without Swift. Conformance
adapters drain real cursors externally and check drain-time errors and final costs;
they must not swap in engine-owned result collection or evade accounting checkpoints.
Independent review covers durability, crypto, accounting and adapters, followed by
integrated tests. Review alone does not establish conformance.

After correctness, preserve a release-build performance baseline, measure optimization
against matching supported-core workloads, and retain checksums, dataset/durability
settings, toolchain/hardware, warmup and exact commands. No parity claim without data.

## Implementation boundaries

Keep flat Swift source files grouped by responsibility in the `Jed` module. Shared
foundations precede dependent work: structured SQLSTATE errors, scalar/type descriptors,
lossless values, exact decimal arithmetic, byte readers/writers and resource accounts.
An indirect open type represents scalar, nominal composite, structural array/range
and query-only inline record types. Typmods and collation descriptors accompany types.
SQL NULL is separate from Boolean false. Text/name equality and ordering use UTF-8
bytes; Swift's canonical-equivalence `String` equality and grapheme `Character` APIs
must not determine SQL semantics. Character-counting kernels use Unicode scalars.

Exact arithmetic is handwritten; Foundation Decimal is not the SQL numeric type.
Canonical large mechanical catalogs may be generated by opt-in Ruby tooling from
shared spec data. Parser, resolver, planner, executor, recursive type behavior and
storage algorithms are never generated. Host clock/entropy, file devices, locks,
transport and spill remain explicit seams. In-memory and durable storage share the
pager and packed-page path; an eager whole-database substitute is not acceptable.

The [crypto audit](swift-native-crypto.md) records selected APIs, pins and native-code
boundaries. Approved libraries are Apple's swift-crypto (including CryptoExtras) and
pinned reference Argon2 with necessary cryptographic backends. Native code is confined
to those utilities and sanctioned OS host calls. No new primitives or unrelated
dependencies are permitted without approval.

### Swift host conversions

The additive ergonomic surface follows api.md §11 through Swift protocols,
without reflection or a second executor. `SQLValueConvertible` converts native
parameters to the existing exact `SQLValue`; `SQLValueDecodable` reads typed row
values. `Optional` is the nullable native target; a nonoptional NULL read is
`22004`, a family mismatch `42804`, and integer narrowing overflow `22003`.
Integer widths, Boolean, Float/Double bit patterns, UTF-8 String/SQLText, bytes,
exact SQLDecimal, UUID, interval and open SQL values have explicit conversions.
Native lists bind as one-dimensional arrays; `[UInt8]` is bytea. Raw SQLValue
retains every temporal and recursive representation without host reinterpretation.

`Row` owns a returned row and exposes exact-name/index access; missing columns
are `42703`. `Rows.nextRow()` remains streaming. Database and Session accept
native `arguments:` alongside the existing typed `parameters:` methods, including
prepared execution. `queryRow` reads one row and closes its cursor;
`queryRows`/`queryMap` collect through the engine's existing Q1-accounted collector.
Argument-conversion errors poison an open transaction; host row-decoding errors
do not masquerade as SQL execution failures. Database scoped view/update helpers
mint one session and use its existing transaction state machine. These APIs are
thread-affine where their underlying Session, Rows or PreparedStatement is.

## Progress and ownership

The durable [progress record](../../impl/swift-native/PROGRESS.md) records slices,
commands/results, failures and next steps. The primary agent owns architecture,
integration, public boundaries and final verification. Delegated work has disjoint
file ownership and agreed interfaces. Commits use `codex/swift-native-experiment`;
they are local-only unless explicitly pushed. No master merge or package publication
is part of this task. Existing unrelated `tasks/memory` files are preserved.
